# HUD refit: slim ribbon, Stores panel, icon rail

The ribbon wraps to a second ragged line once seven goods and the threat
meter are up, and the rail's fifteen tools scroll behind a thin scrollbar
inside 62px. The refit, per the approved canvas
(https://claude.ai/code/artifact/abc3851b-250b-48b1-8406-6871d5816c66):
goods leave the ribbon for a new **Stores** panel in the bottom-left
corner, the ribbon slims to colony facts and stops growing with the
economy, and the rail becomes a 96px two-column icon grid with a caption
strip naming the active tool. Pure `src/ui/` + styleguide change; the
sim, `know/`, and the renderer are untouched.

## Outcome

**What you get:**

- A one-line ribbon at every supported width, carrying colony facts
  only — folk (with the hungry suffix), idle, enclosed, the threat
  meter, the clock — and it never grows again when goods are added.
- A Stores panel in the bottom-left: every good named and counted at a
  glance, grouped wood / stone / food; a future good is one more row.
- A 96px icon rail showing all fifteen tools at once at 768px viewport
  height, with a caption strip naming the active (or hovered) tool and
  its cost.
- A styleguide that matches the screen again — the "wraps rather than
  scrolling" ribbon and the 62px captioned rail are retired from it.

**How to verify:**

- Run the game at 1280×720 and 1920×1080: the ribbon is one line with
  no goods on it; the Stores panel sits bottom-left listing seven
  named counts that move as haulers work.
- At ≥768px window height the rail shows all fifteen tools with no
  scrollbar (at 720 it may scroll, never overlapping Stores); hovering
  or focusing any tool puts its name and cost in the caption strip in
  plain ink, and pressing one keeps them there in gold.
- Tab to a rail tool: the caption strip names it, and its accessible
  name reads "Name — cost". Shrink the window very short: the rail
  scrolls inside itself but never slides under the Stores panel.
- `docs/STYLEGUIDE.md`'s Layout regions describe exactly what is on
  screen; tests and lint pass; the browser console is clean.

## Key decisions

- **Goods move to a Stores panel, bottom-left** (new layout region).
  One row per good — pip, name, count — walked from `GOOD_LIST` exactly
  as the ribbon walks it today, grouped by chain (wood / stone / food)
  with hairline `line-soft` rules and the labour panel's quiet 10px caps
  head. A future good adds a row; the HUD never does ribbon math again.
  Bottom-left mirrors Labour bottom-right; both top corners are already
  spoken for (rail, inspector). Names return to every good — better
  than either ribbon direction managed.
- **The ribbon slims to colony facts** (extends). Brand, folk (with the
  hungry suffix), idle, enclosed, threat meter, then the right-aligned
  clock group — ~900px of typical content, one line at the **minimum
  supported viewport, which this change names as 1280×720** and the
  styleguide records. The threat caption is the one variable-width
  element (the longest "far wilds:" phrases push worst case to
  ~1100px), still inside the 1280 budget.
  `flex-wrap` stays as a safety net but should never fire. Only the
  ribbon's DOM changes: `readout()` and `Readout.goods` are untouched —
  the Stores panel reads the same numbers the ribbon did.
- **Good grouping lives UI-side, beside `GOOD_VAR`** (reuses that
  precedent). A `GOOD_GROUP: Record<ItemTypeValue, "wood" | "stone" |
  "food">` in `hud.ts` maps each good to its group. Grouping is
  presentation, like the pip colour — and the type carries the whole
  forcing function: a new good without an entry is a compile error,
  and a typo'd group is one too, rather than silently minting a fourth
  heading. Adding a genuinely new group means widening the union,
  deliberately.
- **The rail: 96px, icon-only tools in two columns per section**
  (extends the rail anatomy). Same three sections and heads, same
  icons, same pressed recipe (gold text, gold left edge, gold-tint
  fill). Labels and cost captions leave the buttons: each button
  carries `aria-label` and `title` reading "Name — cost" ("Stone wall —
  1 block"), so tooltips serve the pointer and the label serves
  keyboard and screen readers. The honest arithmetic, pinned so the
  build doesn't shave paddings to meet a wrong number: the rail runs
  ~405px (eight button rows at ~33px, grid gaps, three section heads
  ~82px, the caption strip ~40px, padding) with its top at 62px, and
  the Stores panel ~256px with today's seven goods — so rail and
  Stores coexist scroll-free from ~750px of window height. At 768 and
  up nothing scrolls; below that the rail scrolls inside itself,
  gracefully, because both panels live in **one left-edge flex column**
  (rail `flex: 0 1 auto; overflow-y: auto`, Stores fixed beneath it) —
  the browser resolves the split forever, with no hardcoded
  stores-height constant to rot when the eighth good adds a row.
- **A caption strip at the rail's foot names the tool** (new component,
  added to the styleguide in the same change). Fixed height, always
  rendered; priority: the hovered **or keyboard-focused** tool wins,
  else the active tool, else empty — reserved space, so the rail never
  changes height under the pointer, and a keyboard user tabbing
  fifteen unlabeled icons reads each name in the strip rather than
  only in the accessible name. The choice is a pure function
  ((hovered, focused, active) → shown), unit-testable without a DOM.
  Colour keeps the gold budget: the name renders **gold only while the
  strip shows the active tool** — the rail's one gold element,
  restated — and plain ink for hover and focus previews, because hover
  is not intent. Pinned after a build ambiguity: gold follows **which
  tool the strip names**, not why it is named — hovering the tool you
  already hold stays gold rather than flickering to ink under the
  pointer of the button just pressed. Cost in faint 10px beneath. This
  is the always-visible home for the words the buttons gave up.
- **The styleguide is updated in the same change** (the guide and the
  game never disagree). Layout regions rewritten: the ribbon's
  "wraps rather than scrolling" sentence replaced by the slim content
  list, the Stores region added, the rail anatomy re-described
  (96px, two columns, caption strip), and the refit canvas linked at
  the top beside the original reference mock.
- **Zero sim changes** (reuses). No new exports from `sim/know`, no
  commands, no save impact, no renderer work. The hungry suffix, the
  threat meter, and the speed group move markup unchanged.

## Goals

- The ribbon is one line at every width the game supports, and stays
  one line however many goods future steps add.
- All fifteen tools are visible at once at 768px viewport height — no
  scrolling inside the rail in normal play.
- Goods are named and counted at a glance again (the Stores panel),
  scaling to a dozen goods by adding rows.

## Non-goals

- No collapsible groups, tabs, or two-column Stores — one column of
  rows is right until goods outgrow it, and the panel's growth path is
  recorded here rather than built now.
- No rail hotkeys, reordering, or customisation.
- No changes to the inspector, labour panel, menu, or overlays.
- No `sim/` or `sim/know` **behaviour** changes of any kind — with one
  carve-out: comments that name the ribbon as the goods' home may be
  truthed up to say Stores, because a comment that lies about where
  its numbers go is worse than a one-line docs edit across the
  boundary. The class is wider than one file: `Readout`'s doc in
  `know/index.ts`, `GoodDef.label`'s in `sim/goods.ts`, and the
  good-colour rationales in `render/palette.ts` / `render/movers.ts`.
  The build truthed the `src/ui/` and styleguide copies; the sim and
  renderer ones are an owed follow-up on `docs/CLAUDE_TODO.md`.

## Design

### Ribbon (`buildRibbon`)

The goods loop (`for (const good of GOOD_LIST) … this.resource(…)`)
leaves the ribbon. Final content order: brand, folk cluster, idle,
divider, enclosed, divider, threat box, clock. The `.res` recipe is
unchanged for the counts that remain; the per-good `resource()` helper
moves to the Stores panel's builder.

### Stores panel

A new `panel stores` region: `left: 12px; bottom: 12px; width: 150px`,
standard moss-glass recipe, radius 2px. Anatomy top to bottom: 10px
caps head ("Stores", the labour panel's `h4` recipe), then per group —
a 10px caps group label with a `line-soft` rule above it (first group
has none) — then one 13px row per good: 9px rotated pip in the good's
`GOOD_VAR` colour, name in ink-dim, count right-aligned in ink,
tabular numerals. Built once by **bucketing `GOOD_LIST` by
`GOOD_GROUP`**, groups emitted in fixed wood / stone / food order —
never emit-a-label-on-change over enum order, because `ItemType` is
append-only, so a future wood good lands after Bread and would file
itself under Food. `update()` writes one `textContent` per good per
frame through the existing `this.res` map, exactly as the ribbon did.

### Rail (`buildRail`)

Width 96px. Each section head keeps its recipe; below it a
`display: grid; grid-template-columns: repeat(2, minmax(0, 1fr));
gap: 1px` grid of icon-only `.tool` buttons (padding ~8px 0 7px, icon
22×18). Odd counts leave one empty cell — Build's seven tools sit in
four rows. `toolButton()` drops the label and cost spans and gains
`aria-label` / `title` "Name — cost". The caption strip: a fixed-height
footer under the last section (`line-soft` rule above), updated on
pointer enter/leave and on `setTool` — hovered tool wins, else active
tool, else empty. Focus-visible keeps the existing gold outline.

### Styleguide edits

`docs/STYLEGUIDE.md`: the Layout regions section rewrites the ribbon
and rail entries and adds Stores; the caption strip joins "Buttons,
tags, meters"; the guide records **1280×720 as the minimum supported
viewport**; the header's reference-mock line gains the refit canvas's
URL; and any copy in the guide that locates goods "on the ribbon" —
the flour row's "the palest thing on the ribbon" — is reworded, since
the guide and the game never disagree and the goods now live in
Stores. Nothing else in the guide moves.

### Verification

Per `src/ui/CLAUDE.md`: browser-driven via Playwright, at 1280×720
(the minimum supported viewport) and 1920×1080 — the ribbon renders
one line (no wrap), the Stores panel shows seven named counts that
move when the sim's do, tool tooltips and the caption strip carry
name + cost, and the console is clean. The rail's bar is
height-dependent, per the pinned arithmetic: at 720 window height it
may show its internal scroll but must never slide under the Stores
panel; at ≥768 it shows all fifteen tools with no scrollbar. Vitest
covers the caption choice as the pure function above and
`GOOD_GROUP` completeness via its type.

## Alternatives considered

- **Grouped pips in the ribbon** (Ribbon A as first sketched) — one
  line today, but every future good grows the bar again; superseded by
  the Stores panel on the canvas, and kept on its Explorations page.
- **A designed two-line ribbon** (Ribbon B) — everything stays named
  but ~30px of world is spent permanently; not picked.
- **A section flyout rail** (Rail B) — never scrolls and keeps labels,
  but adds a second click to every tool change in a game whose core
  loop is wall-drawing; not picked.
- **`group` as a `GoodDef` field in `sim/goods.ts`** — one table for
  everything about a good, but grouping is presentation and the sim
  table deliberately knows nothing about painting; `GOOD_VAR` set the
  precedent and `GOOD_GROUP` follows it.

## Implementation strategy

*Not part of the design — a starting point for whoever builds this.*

- **Single agent.** The whole diff is `hud.ts`, `hud.css`, a comment
  truth-up in `know/index.ts`, and `docs/STYLEGUIDE.md` — one thread,
  nothing splits. **Sonnet 5 clears this bar**: every decision is
  pinned to exact recipes and numbers; Opus 5 is fine if the session
  already runs it.
- Natural order: the Stores panel + slim ribbon first (pure moves),
  then the rail grid + caption strip (the one new behaviour, built
  around the pure caption-choice function), then the left-edge flex
  column, then the styleguide rewrite — and browser verification at
  both named resolutions before reporting.
